# 当前速度模式测试

当前默认 `CHASSIS_LINK_POSITION_TEST_ENABLE=0`、`CHASSIS_LINK_SELF_TEST_ENABLE=1`，执行 PV（轮廓速度模式，模式值 3）测试。
此前的位置模式往返测试已经由用户在实机上确认成功；以下速度测试仍需重新编译烧录后验证。

## 速度测试动作

每个已就绪节点只执行一次：

```text
+500 脉冲/秒 → 读回确认到速 → 保持 2 秒
→ 0 → 确认停稳 → 等待 1 秒
→ -500 脉冲/秒 → 读回确认到速 → 保持 2 秒
→ 0 → 确认停稳 → 等待 1 秒 → 完成
```

之后才测试下一节点，全部完成后保持零速，不循环。复位 MCU 会重新开始测试。
加减速度均设为 1000 脉冲/秒²，写入后读回确认。模式 6060h=3、6061h=3。
速度模式写 60FFh 目标速度，不写 607Ah 位置目标；启动时先把 60FFh 清零，再完成 6 → 7 → 0Fh 使能。
实际速度和目标速度相差不超过 20 脉冲/秒，并确认状态为已使能且没有故障位，才判为到速或停稳。
错误码与其读取结果继续单独记录；数据只有对应读取状态为 OK 时才有效。
每次运动命令验证窗口为 2 秒。

测试时架空轮子。运行一段时间再暂停查看已存记录，暂停 MCU 不会自动让独立驱动器停车。

## 速度测试 Watch（监视窗口）

```c
g_motorStartupDebug[0].isReady
g_motorStartupDebug[1].isReady
g_motorVelocityDebug[0]
g_motorVelocityDebug[1]
```

`isReady=1` 表示启动使能已验证。`g_motorVelocityDebug` 的槽位与 `g_motorStartupDebug` 相同，以 `nodeId` 判断实际节点。
默认节点 1 左轮，节点 2 右轮。

| 字段 | 含义 |
| --- | --- |
| `result` | 0 尚未测试，1 进行中，2 正反转和两次停止均成功，3 测试失败 |
| `phase` | 当前排队、验证、运行保持、停稳间隔或停止重试阶段 |
| `commandIndex` | 当前第几条命令：0 正转、1 正转后停止、2 反转、3 反转后停止 |
| `commands[0..3]` | 四条命令的完整应答、目标读回、状态字、实际速度和错误码记录 |
| `firstFailure` | 本次测试首个失败的完整记录，停止重试不会覆盖 |
| `hasFailure` | 首次失败记录已有效 |
| `stopRetryCount` | 失败后的停止请求次数 |
| `haltConfirmed` | 测试失败后已验证停稳；正常测试成功时用 result 和 commands 判断，不使用此标志 |

正常完成时四条记录的 `commandValue` 依次为 `500、0、-500、0`，`result` 均为 2。
同一条记录的 `readbackValue` 为 60FFh 目标读回，`actualVelocity` 为 606Ch 实际速度，`effectConfirmed` 为实际验证结果。
验证中这些记录会更新，完成后保留；未执行记录默认 result=0，不把默认字段当作已采样结果。
速度保持阶段不额外周期采样，记录表示到速、停机验证窗口中的反馈；不能将旧记录当作持续在线监控。

启动失败仍看 `g_motorStartupDebug[节点槽位].lastFailure`，模式步骤 2、加速度 3、减速度 4、零速 5、控制字步骤 6～8。
速度模式跳过位置模式专用的步骤 9。启动正常结束在步骤 8；测试运动时 latest/currentStep 会变为步骤 10。

起转、反转或停止验证失败时，正常测试立即结束，仅重试零速；不再次起转或反转。
确认停止后允许测试另一个就绪节点；停止没确认时不切换节点。即使后来停止成功，测试 result 仍为 3，保留失败证据。
未就绪或缺失的节点不启动运动，其他就绪节点可以测试。

## 当前配置与验证范围

- `POSITION_TEST_ENABLE=0`、`SELF_TEST_ENABLE=1`：当前有限速度测试。
- `POSITION_TEST_ENABLE=1`、`SELF_TEST_ENABLE=1`：保留下面的位置测试。
- `SELF_TEST_ENABLE=0`：上位机速度控制，不执行上电自检。

# 保留的位置模式测试说明

开启 `CHASSIS_LINK_POSITION_TEST_ENABLE=1` 时执行 PP（轮廓位置模式，模式值 1）有限位移测试。
使用原 ST-Link 配置；本次不修改 Keil 工程文件、调试器或烧录算法。

## 上电后会做什么

1. 每个节点独立等待心跳、启动网络、设置并读回模式 1。
2. 读取并沿用驱动器现有的正值加减速度，不写 6083h/6084h；6081h 最大速度仍设为 500 脉冲/秒并严格读回验证。
3. 607Ah 目标相对位移先清零；6040h 按 6 → 7 → 0x4F 推进并验证使能。
4. 已就绪的轮子逐个测试：+200 脉冲 → 确认到位且停稳 → 等 1 秒 → -200 脉冲。
5. 每轮只做一次往返，完成后不再循环，电机保持使能锁定。复位 MCU 会重新测试。

测试时架空轮子。200 脉冲对应角度取决于驱动器细分设置，程序不改细分。
驱动器按当前提供的立三手册第 31～34 页控制：0x4F 清除新位置触发，0x5F 产生相对运动触发。
模式 1、读回参数或使能验证不通过时，不触发位移；不自动复位报警。

本模式不向 60FFh 发送速度目标，也不执行上位机速度指令。
位置模式依然需要 6081h 速度上限，这和切换到速度模式是两件事。

SDO 写入使用显式长度的加速传输，首字节必须为 2Fh、2Bh、27h、23h，分别对应 1、2、3、4 字节。
20h 没有加速传输和长度有效标志，不能作为本接口的加速写入命令。
写入最大速度 500 的正确报文为 `601/602: 23 81 60 00 F4 01 00 00`。
驱动器返回 `581/582: 60 81 60 00 ...` 表示下载应答，随后还需读回 6081h 确认值为 500。

## Keil Watch（监视窗口）

```c
g_motorStartupDebug[0]
g_motorStartupDebug[1]
g_motorPositionDebug[0]
g_motorPositionDebug[1]
```

以 `nodeId` 判断节点；默认节点 1 左轮、节点 2 右轮。

### 启动记录 g_motorStartupDebug

- `isReady=1`：启动时已读回确认使能，不代表持续在线监控。
- `attemptCount`：启动尝试次数；只有启动失败重试，位移动作失败不会重新触发。
- `firstSteps`：首次启动历史；`latestSteps`：当前/最近一轮启动历史；`latest`：最近启动命令。
- `lastFailure`：最近一次启动或速度命令失败时的完整记录，自动重试和随后成功不会清空；复位后清空。
- `failureCount`：累计失败次数，为 0 时 `lastFailure` 尚无有效记录。
- `latest.result=PENDING` 且 `endTick=0` 只表示验证正在推进；以 `lastFailure` 或已结束记录诊断失败。
- `commandAccepted`：收到 SDO（服务数据对象）写确认；`effectConfirmed`：读回验证通过。
- 位置测试的步骤 3、4 只有读取，`commandAccepted=false` 正常；`commandValue` 保存所采用的当前值，`readbackValue` 保存再次读取值。
- 这两个步骤的 `commandStatus` 是首次参数读取结果，`verifyReadStatus` 是再次读取结果；读取中止码保存在 `readAbortCode`。
- `statusWord`、`actualVelocity`、`errorCode`：对应读取状态为 0 时才有效。
- `commandAbortCode`：写命令中止码；`readAbortCode`：验证期间最近捕获的非零读取中止码。

| 下标 | 当前默认位置测试的动作 |
| --- | --- |
| 0 | 等待心跳 |
| 1 | NMT（网络管理）启动，验证新心跳和远程控制状态 |
| 2 | 写 6060h=1，读 6061h=1 |
| 3、4 | 读取并沿用现有加速度、减速度，再次读回确认；为零或读取失败时不继续 |
| 9 | 设置并读回 6081h=500，实际执行在第 4 步之后 |
| 5 | 607Ah=0，读回确认；枚举名 ZERO_VELOCITY 为兼容原接口保留，位置测试中实际清零的是位移目标 |
| 6 | 6040h=6，准备好 |
| 7 | 6040h=7，已上电等待使能 |
| 8 | 6040h=0x4F，已使能、相对位置、触发位为 0 |

位置测试结果保存在 `g_motorPositionDebug`，原 `firstStart/firstStop` 是速度自检专用，本模式保持未执行。

### 位移记录 g_motorPositionDebug

| 字段 | 含义 |
| --- | --- |
| `result` | 整个节点测试结果：0 未开始、1 进行中、2 两段均成功、3 失败 |
| `phase` | 当前执行阶段，对照 APP_POSITION_PHASE 枚举 |
| `moveIndex` | 0 正向、1 反向 |
| `moves[0]`、`moves[1]` | 分别保留两段位移的记录 |
| `haltConfirmed` | 失败后已发送 Halt（减速停止），并读回确认速度接近零；正常完成时该字段不使用 |
| `haltAttempts` | 失败后的停止发送次数 |

展开 `moves[0]` 或 `moves[1]`：

- `result`：该段位移结果；`failedPhase` 仅在失败时有意义。
- `relativePulses`：本段 +200 或 -200。
- `startPosition`、`expectedPosition`、`actualPosition`：运动前位置、预期终点和实际读回位置。
- `targetReadback`：607Ah 读回值，必须等于相对位移。
- `actualMode`、`statusWord`、`errorCode`、`actualVelocity`：实际模式和运动反馈。
- `operationStatus[阶段]`：每个独立事务的结果；`abortCode[阶段]`：对应中止码。
- `startTick/endTick`：本段开始/结束毫秒时间。

| operationStatus 下标 | 事务 |
| --- | --- |
| 0 | 读实际模式 6061h |
| 1 | 读运动前实际位置 6064h |
| 2 | 写 6040h=0x4F，清触发位 |
| 3 | 写 607Ah 相对目标 |
| 4 | 读回 607Ah |
| 5 | 写 6040h=0x5F，触发位移 |
| 6 | 读 6041h 状态字 |
| 7 | 读 6064h 实际位置 |
| 8 | 读 606Ch 实际速度 |
| 9 | 读 603Fh 错误码 |
| 12 | 失败后写 6040h=0x010F，减速停止 |
| 13 | 失败后读实际速度确认停稳 |

事务状态：0 成功、1 错误、2 忙、3 超时、4 参数错误、5 未执行/未就绪、6 驱动器中止。
未执行或读取失败的数值不能当作实际反馈。记录是分阶段采样，不是同一时刻的原子快照。

## 怎样认定真的跑成功

必须同时满足：反馈状态为已使能、错误码为 0、状态字目标到达位置有效、
实际位置与预期位置相差不超过 10 脉冲、实际速度绝对值不超过 20 脉冲/秒。
仅收到写入确认、仅有到位标志或仅实际速度为零，都不算动作成功。

每段最多验证 5 秒。任一事务失败或动作超时，记录失败并发送 Halt；
相对位移的触发命令不重试，避免驱动器已执行但应答丢失时多走一段。
停止没有确认前，不开始另一轮；确认停止后，可以测试另一个已就绪节点。
失败节点不自动重复运动，反向段也不会在正向失败后执行。

## 配置与恢复

`User/Config/chassis_link_config.h`：

- `CHASSIS_LINK_POSITION_TEST_ENABLE=1` 且 `CHASSIS_LINK_SELF_TEST_ENABLE=1`：当前有限位置测试。
- 位置测试开关设为 0、自检为 1：执行上面的有限速度自检。
- 自检开关设为 0：恢复原上位机速度控制及速度模式启动验证。

位移、速度、容差和超时均在同一配置文件中。位置测试使用驱动器现有加减速度；速度模式的加减速配置保持原有行为。
